# Decisions

Calls made while building, with the reason. Newest at the bottom of each section.
"Revisit" marks the ones worth a second look.

## Scope and process

- **Migration is a one-off script**, kept in `migrate/` for reference, not a reusable DokuWiki importer. It is re-run while conversion bugs are fixed; once the output is good, `lodge-data` becomes the source and later fixes are made there directly.
- **Layouts, widgets and data files are committed straight into `lodge-data`** after the import, not generated by the script.
- **Login during development: a single local admin account** (user's choice). Users and Discord login come later.

## Content format

- **Pages are CommonMark + GFM** (tables, strikethrough, autolinks) with footnotes and raw HTML allowed. Optional YAML frontmatter.
- **Links and images are standard markdown**, using the page's URL path (`[Label](/ns/page)`, `![alt](/_media/ns/img.jpg)`). Old `[[link]]`s without a label get the target page's title at conversion. Reason: plain markdown everywhere, and a URL copied from the address bar is a valid link.
- **Sized or aligned images use an HTML `<img>` tag** (`width`, `align`); the server scales images to the requested width.
- **Page ids are normalised the DokuWiki way** (lowercase, accents stripped, punctuation and spaces to `-`), so old ids map onto new paths predictably.
- **Boxes and styled text are HTML with a class** (`<div class="spoiler">`, `<span class="badaawi">`), replacing the wrap plugin. CSS selectors are renamed from `.wrap_x` to `.x`.
- **The only additions to markdown are frontmatter and fenced code blocks with the `list` and `widget` languages** (YAML bodies). They show as code in other viewers. No `:::` containers, no `::` directives, no wiki-link syntax.
- **Complex tables (colspan, rowspan, header cells in body rows, no header row) become HTML tables**; simple ones become GFM tables.
- **Smileys become emoji; DokuWiki typography entities (`->`, `(c)`, `...`) become the Unicode characters** at conversion time, so the renderer does no text substitution.
- **`~~NOTOC~~` becomes frontmatter `toc: false`**; `~~NOCACHE~~` is dropped.

## Storage

- **The namespace start page stays `start`** (`foolslanding/start.md`), as in DokuWiki.
- **Media lives in `lodge-data/_media/`, mirroring DokuWiki's paths, and is git-ignored.** The content-hash store with a manifest in git, from the plan, is deferred: the path mirror is simpler and enough for now. Revisit before switch-over.
- **Media history is not imported**, only current media files. Page history is.
- **Special routes live under `/_/`** and page ids may not start with `_`, so they never collide.

## Server

- **The index (titles, backlinks, listings, created/modified dates, search) is in memory**, rebuilt at start-up from the files plus a single `git log` pass. SQLite from the plan is not needed at 1,230 pages. Revisit if start-up gets slow.

## Migration (from the migration script's run)

- **Page history: one commit per DokuWiki change**, with the original author (`user@lodge.invalid`, "anonymous" when empty), date, and `<page id>: <summary>` as message. 11,775 commits.
- **Revisions with no attic copy** (external edits, attic files renamed by the move plugin) are recovered in order from: the same revision under a later id of the page, the move source's last text, the nearest later revision, the current text. 432 of 13,537 changes had nothing recoverable and were skipped.
- **Section anchors are lowercase with `-`** (`#Attack_Rolls` → `#attack-rolls`), matching the renderer's heading ids.
- **`?nolink` and `?direct` image options are dropped**; centre alignment is written as `align="center"` and turned into the `mediacenter` class by the renderer.
- **Bare URLs become `<https://…>` autolinks.** Straight quotes are not turned into curly ones (DokuWiki did that at render time).
- **`list` blocks have three extra keys** beyond the spec, from nspages options: `natural: true`, `label: "{title} ({user})"`, `dates: true`. `-simplelist` becomes `columns: 1`. Without `-textPages` the heading is "Pages in this namespace:", nspages' default.
- **Raw HTML blocks lose their inner blank lines** (except in `<pre>`), so CommonMark keeps each as one HTML block; an HTML-only first line of a paragraph (usually an aligned `<img>`) is split into its own block.
- **Broken DokuWiki source stays broken** (e.g. a link split over two lines); indented lines DokuWiki showed as code stay code.

## Interface (functional changes from the old wiki)

- **The pencil icon opens the editor directly** (one click instead of two). A new menu icon (☰) opens the old slide-in tools panel: page tools (edit, history, backlinks), site tools (recent changes, index) and log in/out. Opening a page with `#menu` opens the panel. Keyboard: `e` edits, `/` searches, `Alt+F` toggles the search box, `Ctrl+S` saves in the editor.
- **Breadcrumbs show where the page sits** (Home › Fool's Landing › Stories › Page) instead of DokuWiki's trail of recently visited pages. The "You are here" label is hidden.
- **The footer reads "Last modified: date by author · history"**, linking to the page history.
- **The editor is a plain text area with Write / Preview / Side by side tabs** (the choice is remembered), live preview, an optional summary, and a warning before leaving with unsaved changes. A page edited by someone else meanwhile is never overwritten: the editor shows both versions. Saving an empty page deletes it (as in DokuWiki).
- **History lists every change with author, summary and age**, each with "changes" (diff), "view" (old version) and "restore" (creates a new edit; nothing is lost).
- **Search redirects straight to a page whose title matches exactly**; otherwise it lists results with a snippet.
- **A namespace without a start page shows an automatic list of its pages**, and links to it are no longer red.
- **Data files (`.json`) can be edited in the browser** (`/_/edit/path.json`) and are checked to be valid JSON before saving.
- **Old DokuWiki URLs redirect**: `/doku.php?id=a:b` and `/a:b` go to `/a/b`.
- **Development flags**: `--public` allows reading without logging in; `--as <user>` makes every request act as that user (screenshots and local testing only).
- **Files view (`/_/files`, in the menu for editors)** browses the whole content repo except media: pages, data files, layouts and widgets, with edit, history and open links, and a "new file" box (a name without extension creates a page). Any text file (`.json`, `.css`, `.js`, `.html`, …) is edited with the same editor and history as pages. **Folders starting with `_` (`_layout`, `_widgets`) are admin-only**, because their code runs in every reader's browser. JSON must be valid and a layout's `page.html` must parse before they are saved, so a typo cannot take the site down.
- **Moving and renaming** (`/_/mv`, "move" links in Files, "Rename" in the page tools) works for a page, a whole folder of pages, and media files or folders. Every link and image reference to what moved is rewritten across the wiki in the same commit; a moved page's own relative links are made absolute so they keep working. Moving a page folder can take its `_media` folder of the same name along. Widget settings naming a data file (`data: x/y.json`) are not rewritten (the form says so).
- **Media appears in Files as a thumbnail grid** with size, "used by" (pages referring to it, including widget settings) and a copy-address button, plus upload. Media is not in git, so **delete only works for files no page, data file, layout or widget uses, and moves them to `_media/.trash/<date>/` instead of erasing them.** A replaced upload keeps its previous version there too. The bin is never listed or served.
- **The editor uses CodeMirror 5** (MIT, vendored as `internal/server/static/cm.js`, ~600 KB, loaded only on the edit page; no CDN, works offline) for syntax highlighting: Markdown (GitHub flavour, with YAML frontmatter and fenced blocks highlighted in their language; `list` and `widget` blocks as YAML, raw HTML as HTML), JavaScript, JSON, CSS, HTML, YAML and SVG. Code files get line numbers, active-line highlight and auto-closing brackets; pages get soft wrapping. Ctrl+F searches, Tab/Shift+Tab indent. If the script fails to load, the plain text area still works.
- **"New page" is in the menu on every page** (editors): a form with a title and a folder (pre-filled with the current page's folder, with autocompletion of existing folders). The address is made from both; if that page exists you are taken to it, otherwise to the editor with the title as first heading. Creating a page by visiting a missing address still works. **The Index entry is gone from the menu** (`/_/index` still exists).

## Accounts

- **The DokuWiki accounts are imported with their password hashes** (`--import-users ../public_html/conf/users.auth.php`), so everyone keeps their password (all 43 are bcrypt, which Go checks directly). Groups map to roles: `admin` → admin (3), `user` → editor (25), anything else → **pending** (15: registered but never approved in DokuWiki, several look like spam). Service accounts (`carto`, the notifier bot) are skipped by group. Accounts live in the content repo (see below).
- **Roles: pending (no access, sees "waiting for approval"), reader, editor, admin.** Admins manage accounts on `/_/users` (role, new password, delete, add); everyone can change their own password on `/_/account`. Changing a password logs out that account's other sessions. Deleting an account keeps its edits in the history under its name.
- **Failed logins are limited to 8 a minute per address.** User names are case-insensitive.
- **Discord login is postponed:** it needs a Discord application (client id and secret) and the wiki's public address for the OAuth redirect.
- **Everything that matters lives in the content repo; the state folder is disposable.** Accounts are in `_config/users.json` (bcrypt hashes, real names, emails), versioned and backed up with the rest; every account change is a commit by whoever made it, with a neutral message (never a password or email). The state folder only holds the session key (regenerated if lost: everyone is logged out; it must never be in git, as it can forge logins) and the scaled-image cache. Accounts from an older `<state>/users.json` move into the repo on start. Trade-off: hashes and emails stay in git history, so the data repo must stay private, and fully erasing a person means rewriting history.
- **`_config/` is private: only admins see it**, in Files, history and diffs (others get "not found"); raw and static routes never serve it. Webhook addresses for notifications will go there too.
- **Media manifest: `_config/media.json`** lists every media file (size, SHA-256, modification time), one line per file, with the bin (`_media/.trash`) in its own `trash` section. The server commits it after every upload, replacement, move (in the same commit as the pages it rewrites) and delete, and brings it up to date at start-up for files added outside the wiki (hashes are only recomputed when size or date change). Media therefore has a visible history, and a separate backup tool can copy and verify everything from it. Emptying the bin will drop its entries.
- **The start-up manifest sync never records a mass removal** (more than 20 files and over half the list missing): it logs a warning instead, so a missing or half-copied media folder on a fresh server cannot make a backup tool believe everything was deleted.
- **Everyone can edit their real name and email on `/_/account`** (only admins see them); the account and users pages are in the menu's User Tools.
