# Decisions

Calls made while building, with the reason. Newest at the bottom of each section; the
last section holds the later decisions in order. "Revisit" marks the ones worth a second
look; *Superseded* marks a call replaced by a later one (kept for the record).

## Scope and process

- **Migration is a one-off script**, kept in `migrate/` for reference, not a reusable DokuWiki importer. It is re-run while conversion bugs are fixed; once the output is good, `lodge-data` becomes the source and later fixes are made there directly.
- **Layouts, widgets and data files are committed straight into `lodge-data`** after the import, not generated by the script.
- *Superseded (see Accounts):* **Login during development: a single local admin account** (user's choice). Users and Discord login come later.

## Content format

- **Pages are CommonMark + GFM** (tables, strikethrough, autolinks) with footnotes and raw HTML allowed. No frontmatter (removed: only one page used it, for `toc: false`).
- **Links and images are standard markdown**, using the page's URL path (`[Label](/ns/page)`, `![alt](/_media/ns/img.jpg)`). Old `[[link]]`s without a label get the target page's title at conversion. Reason: plain markdown everywhere, and a URL copied from the address bar is a valid link.
- **The conversion wrote sized or aligned images as HTML `<img>` tags** (`width`, `align`); the server scales images to the requested width. New images use the layout presets instead (see "Image layout" below); converting the old tags is on the to-do list.
- **Page ids are normalised the DokuWiki way** (lowercase, accents stripped, punctuation and spaces to `-`), so old ids map onto new paths predictably.
- **Boxes and styled text are HTML with a class** (`<div class="spoiler">`, `<span class="badaawi">`), replacing the wrap plugin. CSS selectors are renamed from `.wrap_x` to `.x`.
- **The only additions to markdown are fenced code blocks with the `list` and `widget` languages** (YAML bodies). They show as code in other viewers. No `:::` containers, no `::` directives, no wiki-link syntax.
- **Complex tables (colspan, rowspan, header cells in body rows, no header row) become HTML tables**; simple ones become GFM tables.
- **Smileys become emoji; DokuWiki typography entities (`->`, `(c)`, `...`) become the Unicode characters** at conversion time, so the renderer does no text substitution.
- **`~~NOTOC~~` and `~~NOCACHE~~` are dropped**: the table of contents appears with 3 headings or more.

## Storage

- **The namespace start page stays `start`** (`foolslanding/start.md`), as in DokuWiki.
- **Media lives in `lodge-data/_media/`, mirroring DokuWiki's paths, and is git-ignored.** No content-hash store: the path mirror is simpler, and a manifest of hashes in git (`_config/media.json`, see Accounts) gives the history and the backup check the store was meant for.
- **Media history is not imported**, only current media files. Page history is.
- **Special routes live under `/_/`** and page ids may not start with `_`, so they never collide.

## Server

- **The index (titles, backlinks, listings, created/modified dates, search) is in memory**, rebuilt at start-up from the files plus a single `git log` pass. SQLite from the plan is not needed at 1,230 pages. Revisit if start-up gets slow.

## Migration (from the migration script's run)

- **Page history: one commit per DokuWiki change**, with the original author (`user@lodge.invalid`, "anonymous" when empty), date, and `<page id>: <summary>` as message. 11,775 commits.
- **Revisions with no attic copy** (external edits, attic files renamed by the move plugin) are recovered in order from: the same revision under a later id of the page, the move source's last text, the nearest later revision, the current text. 432 of 13,537 changes had nothing recoverable and were skipped.
- **Section anchors are lowercase with `-`** (`#Attack_Rolls` → `#attack-rolls`), matching the renderer's heading ids.
- **`?nolink` and `?direct` image options are dropped**; centre alignment is written as `align="center"` and turned into the `center` class by the renderer.
- **Bare URLs become `<https://…>` autolinks.** Straight quotes are not turned into curly ones (DokuWiki did that at render time).
- **`list` blocks have three extra keys** beyond the spec, from nspages options: `natural: true`, `label: "{title} ({user})"`, `dates: true`. `-simplelist` becomes `columns: 1`. Without `-textPages` the heading is "Pages in this namespace:", nspages' default.
- **Raw HTML blocks lose their inner blank lines** (except in `<pre>`), so CommonMark keeps each as one HTML block; an HTML-only first line of a paragraph (usually an aligned `<img>`) is split into its own block.
- **Broken DokuWiki source stays broken** (e.g. a link split over two lines); indented lines DokuWiki showed as code stay code.

## Interface (functional changes from the old wiki)

- *Superseded by layout v2 (sidebar, no icons or panel):* **The pencil icon opens the editor directly** (one click instead of two). A new menu icon (☰) opens the old slide-in tools panel: page tools (edit, history, backlinks), site tools (recent changes, index) and log in/out. Opening a page with `#menu` opens the panel. Keyboard: `e` edits, `/` searches, `Alt+F` toggles the search box, `Ctrl+S` saves in the editor.
- **Breadcrumbs show where the page sits** (Home › Fool's Landing › Stories › Page) instead of DokuWiki's trail of recently visited pages. The "You are here" label is hidden.
- **The footer reads "Last modified: date by author · history"**, linking to the page history.
- **The editor is a plain text area with Write / Preview / Side by side tabs** (the choice is remembered), live preview, an optional summary, and a warning before leaving with unsaved changes. A page edited by someone else meanwhile is never overwritten: the editor shows both versions. Saving an empty page deletes it (as in DokuWiki).
- **History lists every change with author, summary and age**, each with "changes" (diff), "view" (old version) and "restore" (creates a new edit; nothing is lost).
- **Search redirects straight to a page whose title matches exactly**; otherwise it lists results with a snippet.
- **A namespace without a start page shows an automatic list of its pages**, and links to it are no longer red.
- **Data files (`.json`) can be edited in the browser** (`/_/edit/path.json`) and are checked to be valid JSON before saving.
- **Old DokuWiki URLs redirect**: `/doku.php?id=a:b` and `/a:b` go to `/a/b`.
- **Development flags**: `--public` allows reading without logging in; `--as <user>` makes every request act as that user (screenshots and local testing only).
- **Files view (`/_/files`, in the menu for editors)** browses the whole content repo except media: pages, data files, layouts and widgets, with edit, history and open links, and a "new file" box (a name without extension creates a page). Any text file (`.json`, `.css`, `.js`, `.html`, …) is edited with the same editor and history as pages. **Folders starting with `_` (`_layout`, `_widgets`) are admin-only**, because their code runs in every reader's browser. JSON must be valid and a layout's `page.html` must parse before they are saved, so a typo cannot take the site down.
- **Moving and renaming** (`/_/mv`, "move" links in Files, "Rename" in the page tools) works for a page, a whole folder of pages, and media files or folders. Every link and image reference to what moved is rewritten across the wiki in the same commit; a moved page's own relative links are made absolute so they keep working. Moving a page folder can take its `_media` folder of the same name along. Widget settings naming a data file (`data: x/y.json`) are not rewritten (the form says so).
- **Media appears in Files as a thumbnail grid** with size, "used by" (pages referring to it, including widget settings) and a copy-address button, plus upload. Media is not in git, so **delete only works for files no page, data file, layout or widget uses, and moves them to `_media/.trash/<date>/` instead of erasing them.** A replaced upload keeps its previous version there too. The bin is never listed or served.
- **The editor uses CodeMirror 5** (MIT, vendored as `internal/server/static/cm.js`, ~600 KB, loaded only on the edit page; no CDN, works offline) for syntax highlighting: Markdown (GitHub flavour, with fenced blocks highlighted in their language; `list` and `widget` blocks as YAML, raw HTML as HTML), JavaScript, JSON, CSS, HTML, YAML and SVG. Code files get line numbers, active-line highlight and auto-closing brackets; pages get soft wrapping. Ctrl+F searches, Tab/Shift+Tab indent. If the script fails to load, the plain text area still works.
- **"New page" is in the menu on every page** (editors): a form with a title and a folder (pre-filled with the current page's folder, with autocompletion of existing folders). The address is made from both; if that page exists you are taken to it, otherwise to the editor with the title as first heading. Creating a page by visiting a missing address still works. **The Index entry is gone from the menu** (`/_/index` still exists).

## Accounts

- **The DokuWiki accounts are imported with their password hashes** (a one-off import, done on 2026-11-18; the code is in the git history), so everyone keeps their password (all 43 are bcrypt, which Go checks directly). Groups map to roles: `admin` → admin (3), `user` → editor (25), anything else → **pending** (15: registered but never approved in DokuWiki, several look like spam). Service accounts (`carto`, the notifier bot) are skipped by group. Accounts live in the content repo (see below).
- **Roles: pending (no access, sees "waiting for approval"), reader, editor, admin.** Admins manage accounts on `/_/users` (role, new password, delete, add); everyone can change their own password on `/_/account`. Changing a password logs out that account's other sessions. Deleting an account keeps its edits in the history under its name.
- **Failed logins are limited to 8 a minute per address.** User names are case-insensitive.
- **Discord login is postponed:** it needs a Discord application (client id and secret) and the wiki's public address for the OAuth redirect.
- **Everything that matters lives in the content repo; the state folder is disposable.** Accounts are in `_config/users.json` (bcrypt hashes, real names, emails), versioned and backed up with the rest; every account change is a commit by whoever made it, with a neutral message (never a password or email). The state folder only holds the session key (regenerated if lost: everyone is logged out; it must never be in git, as it can forge logins) and the scaled-image cache. Accounts from an older `<state>/users.json` move into the repo on start. Trade-off: hashes and emails stay in git history, so the data repo must stay private, and fully erasing a person means rewriting history.
- **`_config/` is private: only admins see it**, in Files, history and diffs (others get "not found"); raw and static routes never serve it. Webhook addresses for notifications will go there too.
- **Media manifest: `_config/media.json`** lists every media file (size, SHA-256, modification time), one line per file, with the bin (`_media/.trash`) in its own `trash` section. The server commits it after every upload, replacement, move (in the same commit as the pages it rewrites) and delete, and brings it up to date at start-up for files added outside the wiki (hashes are only recomputed when size or date change). Media therefore has a visible history, and a separate backup tool can copy and verify everything from it. Emptying the bin will drop its entries.
- **The start-up manifest sync never records a mass removal** (more than 20 files and over half the list missing): it logs a warning instead, so a missing or half-copied media folder on a fresh server cannot make a backup tool believe everything was deleted.
- **Everyone can edit their real name and email on `/_/account`** (only admins see them); the account and users pages are in the menu's User Tools.
- **Files the server writes itself are marked in Files.** `_config/media.json` is read-only ("view"; the editor has no Save button and the server refuses saves). `_config/users.json` is editable with a warning, for repairs; a save must keep a bcrypt hash and a valid role for every account, and the accounts are reloaded right after.
## Later decisions

- **No side-by-side comparison with the running old wiki**: the user reviewed the result and judged the look correct (2026-11-18).
- **Layout v2 (2026-11-18): a sticky sidebar instead of the header icons and slide-in panel, and no layout script at all.** The sidebar holds the table of contents, the page tools (edit, history, rename, backlinks), the wiki tools (search, recent changes, new page, files) and the account entries. The header keeps only the title. On narrow screens (≤ 900 px) the sidebar moves below the content and the header shows a "Menu ↓" link to it. Search is a page reached from the sidebar. The column width is a CSS variable, `--lw-col`, which the map and calendar widgets widen. The Eloise/Varfew glitch easter egg is removed (it is in the history of `_layout/script.js`).
- **Clean HTML and a new stylesheet (2026-11-18).** The renderer no longer imitates DokuWiki's markup (no section divs, `div.li`, `wikilink1`, `mediaright`...): headings get ids; links to missing pages get `missing`, external links `external`; images get `left`/`right`/`center` and link to the full file (`a.image`); tables sit in a scrollable `div.table-wrap`; the TOC is `nav.toc`; listings are one list laid out with CSS columns (`--columns`), picture listings show a title card for pages without a picture. The layout is a short semantic `page.html` (header, main, article, aside) and a ~300-line `style.css` written from the old template's sources, with the palette and fonts as CSS variables (Skarnholm only overrides those). Libre Baskerville is now self-hosted (no request to Google Fonts). Visual tweaks: 16px text with more line height, parchment cards with soft shadows, external links marked ↗, missing links dashed, visible keyboard focus, spoilers blurred until hovered or tapped (they were text in the background colour), a print style. The compiled DokuWiki CSS and its build tool are gone (in the history).
- **Pages know their creator.** The history scan follows renames and, for the imported history, DokuWiki moves ("↷ Page moved from …"), so a moved page keeps its original author and creation date. In `list` labels, `{user}` is the creator (as in nspages, which the log listings used), `{editor}` the last author.
- **Notifications reproduce the old lodgenotifier plugin**, configured in `_config/notifications.json` (admin-only; the three rules and their webhook addresses were copied from DokuWiki's config): each rule has `on` (create, edit, delete, revert), optional `namespaces` (pages directly in these folders), a Discord embed `template` with `%id% %url% %title% %abstract% %user% %summary% %type% %type-past%`, optional colours per change type and `attach-image` (the page's first image, uploaded with the message). `base_url` gives the public address for links. They fire on page saves, deletes, reverts and page writes from widgets; not on renames or data files. **Nothing is sent unless the server runs with `--notify`**; otherwise each message that would be sent is logged.
- **Deployment is one idempotent script, `deploy/setup.sh`** (Debian/Ubuntu, run with sudo from a clone of lodge-wiki), configured by `deploy/lodge.conf` (not committed). Each run: installs missing packages (Go at the `go.mod` version from go.dev, Caddy from its repository), creates the `lodge` service account and its SSH deploy key, clones the data repo (merging is left to the wiki's `--sync`), pulls and rebuilds the code, writes a sandboxed systemd unit and the Caddyfile, restarts and checks the wiki answers, and warns if media is missing. `--sync` (below) keeps the server and GitHub in step. Behind Caddy, the login limit uses `X-Forwarded-For` (trusted from localhost only) and the session cookie is HTTPS-only.
- **Deleting a page is saving it empty**: the file is removed in a commit and its history is kept. The Delete tool only adds a confirmation page that posts an empty text to the editor; a deleted page's address says so and links to its history.
- **The user guide (`docs/guide.md`) is embedded in the program** and shown at `/_/help`, followed by each widget's `_widgets/<name>/README.md` from the content repo, so the documentation of group-specific widgets lives with them.
- **Image layout is decided by the wiki, not by authors**: plain markdown images; one alone in its paragraph is centred and height-capped (portraits stay reasonable), a title becomes a caption (`<figure>`), images alone together become a gallery of equal tiles. The only knobs are five presets in the address's fragment (`#small`, `#medium`, `#full`, `#left`, `#right`, combinable as `#small-right`): valid markdown and URLs that other viewers ignore, sizes defined by the layout's CSS. Rejected: `{width=…}` attribute syntax (non-standard, shows as text elsewhere) and floating by position in the text (invisible rules, as DokuWiki's space-based alignment was).
- **Images are served scaled by default**: unsized raster images are requested at 800 CSS pixels (1600 real), presets at their size; explicit HTML `width`/`height` still win. The core's image CSS uses `:where()` (zero specificity) so a layout can restyle any of it.
- **The wiki syncs with its upstream itself (`--sync`)**: fetch, merge, push; seconds after its own commits, every 5 minutes, at start-up, and on an admin's **Sync now**. Fetch and push run outside the write lock, the merge inside it. A merge, not a rebase: rebasing would rewrite commit ids, which the editor uses as base revisions (false conflicts for anyone editing). **On conflict the wiki's version of the whole file wins** (not line by line, which could produce a broken mix, e.g. in `users.json`): a conflict means a player and an admin changed the same file, and the admin can redo theirs, which stays in the history as the merge's second parent. The merge commit message and the admin's status on Recent changes list those files. After a merge the index is rebuilt and the accounts reloaded if `users.json` changed.
- **Finding and linking by title, writing standard links**: one finder (fuzzy, accent-insensitive, on titles and addresses, all titles loaded once from `/_/titles`) serves the quick jump and link insertion. `[[` only opens the finder; what lands in the page is a plain markdown link to the page's address, so pages stay standard (no wiki-link syntax).
- **No structured pages (for now)**: a wiki was chosen over a campaign manager for its flexibility; typed records with fixed fields would bring back "the feature we need doesn't exist" and break on exceptions. To explore later: records parsed from the conventions pages already follow, without changing the format.
- **No drag and drop in the Files view**: moving things there is rare, and a typed path is precise and rewrites links. Dropping images into the editor, where people need them, is supported.
- **No top bar (2026-11-18)**: it only repeated the site title, which the breadcrumbs' first link already gives (the home page with both campaigns). On narrow screens "Menu ↓" sits at the right of the breadcrumbs.
- **`deploy/setup.sh` pulls the code first and restarts itself if that changed it**, so a fix to the script applies on the run that fetched it (bash would otherwise carry on with the old script).
- **Security review (2026-11-18)**, after a code review found real holes, now fixed and covered by `internal/server/security_test.go` (each test was checked to fail on the old code):
  - revisions from requests must be commit hashes (`wiki.ValidRev`) and are passed after `--end-of-options`: `?rev=--output=…` made git write files;
  - every git command runs with `GIT_LITERAL_PATHSPECS=1`: `*config/users.json` matched the private accounts file in diffs;
  - every user-supplied path goes through `fileAccess`/`MediaPath`, which use `filepath.IsLocal`: an editor could move `_media/../../lodge-state/session.key` into the media folder and forge an admin login;
  - writes refuse paths outside the repository, and a failed commit puts the files back;
  - accounts are copy-on-write and the index is swapped atomically under one rebuild lock (data races, lost index updates);
  - cross-site form posts are refused (Go's `http.CrossOriginProtection`; this is the CSRF protection, no tokens needed);
  - git commands time out and never prompt; the server shuts down gracefully, so a restart cannot leave a stale git lock.
- **Editors can put HTML, and so scripts, in pages** (raw HTML is allowed, as in the old wiki). Accepted: editors are the group's players, every change is a commit with their name and can be reverted. SVG files are served with a policy that stops their scripts when opened directly, and widget names are restricted to `a-z0-9-`. Revisit if editing is ever opened to strangers.
